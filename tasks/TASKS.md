- [x] 001.10 Compose wiring — Added a `pg_isready`-based healthcheck to the `db` service (`interval: 5s, timeout: 5s, retries: 5, start_period: 5s`), and changed `backend`'s `depends_on` from the short-form list to `db: condition: service_healthy` — plain `depends_on` only waits for the db *container to start*, not for Postgres to actually accept connections, which would otherwise race the backend's migrate-then-serve entrypoint (crash-loop on first boot, saved by `restart: unless-stopped` but non-deterministic). `frontend` keeps a plain (non-healthcheck-gated) `depends_on: [backend]` since nginx only serves static files already baked into its image — nothing at frontend startup talks to the backend to gate on; the browser is the actual caller, later, over the network. **Crossed into backend code**: the backend had no CORS handling, so browser calls from the frontend origin (`http://localhost:5173`) to the backend origin (`http://localhost:3000`) would have been blocked client-side even though curl worked fine (curl doesn't enforce CORS).
